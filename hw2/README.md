# HW2 — Порушення принципу підстановки Лісков (LSP)

## Що таке LSP?
Принцип підстановки Лісков (Liskov Substitution Principle) означає, що об’єкти дочірнього класу повинні коректно замінювати об’єкти батьківського класу без порушення логіки програми.

---

## Приклад 1: Bird → Penguin

### Порушення:
Клас `Bird` має метод `fly()`, але пінгвін літати не може.

### Чому це порушує LSP:
Якщо код очікує, що будь-який `Bird` може літати, підстановка `Penguin` призведе до помилки або некоректної поведінки.

### Проблеми:
- Винятки під час виконання
- Некоректна логіка програми

### Рішення:
Розділити класи:
- `FlyingBird`
- `NonFlyingBird`

---

## Приклад 2: Payment → CashPayment / CreditCardPayment

### Порушення:
Базовий клас `Payment` дозволяє скасування платежу, але `CashPayment` не може бути скасований.

### Чому це порушує LSP:
Дочірній клас змінює поведінку базового класу, що ламає очікування коду.

### Проблеми:
- Логічні помилки
- Неконсистентна поведінка

### Рішення:
Розділити інтерфейси:
- `RefundablePayment`
- `NonRefundablePayment`

---

## Приклад 3: File → ReadOnlyFile

### Порушення:
Базовий клас `File` дозволяє запис, але `ReadOnlyFile` забороняє зміну.

### Чому це порушує LSP:
Код, який працює з `File`, очікує можливість запису, але отримує помилку.

### Проблеми:
- Винятки під час роботи
- Порушення контракту класу

### Рішення:
Створити окремі інтерфейси:
- `Readable`
- `Writable`

---

## Висновок
Для дотримання LSP потрібно проєктувати ієрархії так, щоб дочірні класи не змінювали очікувану поведінку базових класів, а також розділяти відповідальність через інтерфейси.
