Factory vs Abstract Factory: вибір

Породжувальні патерни проєктування спрямовані на гнучке створення об’єктів без жорсткої прив’язки до конкретних класів. Серед них важливе місце займають Factory Method та Abstract Factory. Обидва патерни вирішують проблему створення об’єктів, але відрізняються масштабом застосування та рівнем абстракції.

Factory Method визначає інтерфейс для створення об’єкта, але дозволяє підкласам вирішувати, який саме клас інстанціювати. У цьому підході базовий клас оголошує фабричний метод, а конкретні підкласи перевизначають його та повертають конкретний тип продукту. Таким чином, клієнтський код залежить лише від абстракції, а не від конкретних реалізацій. Це забезпечує слабке зв’язування та дозволяє легко додавати нові типи продуктів без зміни існуючого клієнтського коду.

Factory Method доцільно використовувати тоді, коли клас не може наперед визначити, який саме об’єкт потрібно створити, або коли створення об’єкта потрібно делегувати підкласам. Наприклад, система логування може мати різні реалізації логера — консольний, файловий або мережевий. Клієнт працює з фабрикою, а не з конкретними логерами. Додавання нового типу логера потребує створення нової фабрики, але не змінює вже існуючий код.

Abstract Factory є більш масштабним патерном. Він надає інтерфейс для створення сімейства взаємопов’язаних об’єктів без вказування їх конкретних класів. На відміну від Factory Method, який створює один продукт, Abstract Factory створює групу пов’язаних продуктів, що повинні працювати разом. Клієнт отримує фабрику, яка відповідає певній конфігурації системи, і через неї створює всі необхідні об’єкти.

Abstract Factory доцільно використовувати, коли система повинна підтримувати кілька сімейств взаємопов’язаних об’єктів. Наприклад, графічний інтерфейс може мати окремі реалізації для Windows та macOS. Фабрика для Windows створює кнопку, поле введення та меню у стилі Windows, а фабрика для macOS створює ті самі елементи, але в іншому стилі. Клієнт працює лише з абстракціями і може легко переключитися між сімействами продуктів, змінюючи лише фабрику.

Основна різниця між Factory Method та Abstract Factory полягає в тому, що перший створює один продукт через перевизначення методу, а другий створює ціле сімейство взаємопов’язаних продуктів через окремий об’єкт-фабрику. Factory Method є простішим у реалізації і підходить для розширення одного типу об’єкта. Abstract Factory є складнішим, але забезпечує узгодженість між кількома об’єктами однієї конфігурації.

Перевагою Factory Method є простота, дотримання принципу відкритості/закритості та слабке зв’язування. Недоліком може бути збільшення кількості підкласів. Abstract Factory забезпечує узгодженість продуктів та зручність перемикання між конфігураціями, але додає більше абстракцій і ускладнює структуру системи. Крім того, додавання нового типу продукту може вимагати змін у всіх конкретних фабриках.

Таким чином, вибір між Factory Method та Abstract Factory залежить від складності системи. Якщо потрібно гнучко створювати один тип об’єкта, достатньо Factory Method. Якщо ж система має кілька сімейств пов’язаних об’єктів, які повинні працювати разом, доцільніше використовувати Abstract Factory.
